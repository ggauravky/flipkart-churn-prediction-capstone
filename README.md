## Part 1 findings

- **R1.1 (Hypothesis Testing & Practical Size):** The null hypothesis $H_0: \mu = 8.0$ (representing the INR 800 planning assumption) was **rejected** (`reject_h0 = yes`). The computed test statistic is `z_stat = 2.8930`, which exceeds the two-tailed critical value of $1.96$ at $\alpha = 0.05$. In domain terms, a Type I error would occur if Flipkart's category planning team falsely concludes that average order values have shifted away from INR 800 (triggering costly, unnecessary revisions to category margin targets, promotional minimums, and inventory allocations) when customer order values were actually still averaging INR 800. The observed sample mean is `mean_value = 8.9382`, representing an increase of `8.9382 - 8.0 = 0.9382` column units (**INR 93.82 per order**, an 11.73% lift). In this simulated e-commerce scenario, an observed difference of ~INR 94 per basket is practically meaningful within the study's decision parameters. However, because these records are generated by a synthetic data-generating process (`generate_data.py`), these findings illustrate the decision-intelligence methodology and statistical inference workflow rather than proving actual business metrics or operational outcomes for the live Flipkart enterprise.

- **R1.2 (Sample Sizing for Planning):** Sizing a future study to estimate the mean order value within a margin of error $E = 0.5$ column units (INR 50) at 95% confidence requires `n_required = 1293` records, calculated from the sample standard deviation `sd_value = 9.1723`. Compared to the 800 records currently available, our dataset is undersized for that degree of precision (yielding an actual margin of error of $\pm 0.6356$ units or $\pm \text{INR } 63.56$). For the planning team, this means that before making high-stakes budgetary or category decisions requiring $\pm \text{INR } 50$ precision, they must either pool an additional 493 customer transactions or accept a wider uncertainty band ($\pm \text{INR } 64$) when relying on the current sample.

- **R1.3 (Convergence of Gradient Descent):** Batch gradient descent converged exactly to the analytical least-squares regression line, yielding `gd_slope_gap = 0.0000` (far below the 0.001 threshold) with final `gd_slope = 0.6701` and `gd_intercept = -3.6598`. Gradient descent reached the closed-form line because the mean squared error loss surface of linear regression is strictly convex with a single global optimum, and standardizing $X_4$ ensured well-conditioned, spherical contours that permitted the fixed learning rate $\eta = 0.1$ to progress directly to the analytical minimum without oscillation.

- **R1.4 (Residual Funnel & Log Transformation):** The raw linear regression model exhibits a pronounced funnel pattern (heteroskedasticity), with `resid_sd_ratio_raw = 3.7525`: the residual sample standard deviation in the upper half of fitted values (`resid_sd_upper_raw = 8.6891`) is approximately 3.75 times that of the lower half (`resid_sd_lower_raw = 2.3155`), which is inconsistent with the constant-variance assumption of ordinary least squares. After transforming both variables to logarithms, the log-log regression of $\ln(\text{value})$ on $\ln(X_4)$ yields `resid_sd_ratio_log = 1.0396` (`resid_sd_upper_log = 0.5369` vs. `resid_sd_lower_log = 0.5165`), substantially reducing the upper-to-lower residual spread ratio to near parity and effectively removing the median-split funnel pattern observed on the raw scale.

- **R1.5 (Multiple Regression Predictors & Model Comparison):** In the multiple regression of $\ln(\text{value})$ on eight design columns, the predictors whose coefficients have an absolute value strictly above $0.05$ (excluding the intercept `mr_beta_0 = -1.8613`) are:
  1. $\ln(X_4)$ (`avg_order_value_inr_hundreds` in log space): `mr_beta_1 = 1.1576`
  2. $X_2$ (`complaint_count_90d`): `mr_beta_3 = 0.0940`
  3. $X_3$ (`discount_order_share`): `mr_beta_4 = 0.1067`
  4. $X_6$ (`cod_flag`): `mr_beta_6 = 0.1518`
  *(The remaining predictors had $|\hat{\beta}_j| \le 0.05$: $X_1$ tenure with $-0.0074$, $X_5$ loyalty with $0.0028$, and $X_7$ plus member flag with $0.0172$).*
  Comparing the multiple regression adjusted $R^2$ of `mr_adj_r2 = 0.7403` against the bivariate log-log adjusted $R^2$ of `loglog_adj_r2 = 0.6561` reveals an increase of **0.0842 (8.42 percentage points)**. Because adjusted $R^2$ penalizes additional degrees of freedom, this substantial improvement confirms that the additional predictors genuinely earn their place in explaining customer order values.

## Part 2 findings

- **R2.1 (Learning-Rate Sensitivity):** Ordering the three Task 2.3 training losses after 200 epochs from lowest to highest yields:
  $$\text{loss\_epoch\_200\_eta\_1.0 } (0.3703) < \text{loss\_epoch\_200\_eta\_0.1 } (0.3776) < \text{loss\_epoch\_200\_eta\_0.01 } (0.5091)$$
  This demonstrates that an overly small learning rate ($\eta = 0.01$) progresses sluggishly and remains underfitted far from the minimum after 200 iterations, whereas on standardized features with a smooth convex loss surface, a large learning rate ($\eta = 1.0$) rapidly descends the gradient directly to the optimal cost basin without instability or divergence.

- **R2.2 (Predictor Weights & Odds Ratio Interpretation):** The three predictors with the largest absolute weights in the logistic regression model are:
  1. $X_3$ (`discount_order_share`): `weight_X3 = 0.9013` ($|w| = 0.9013$), `odds_ratio_X3 = 2.4629`
  2. $X_1$ (`customer_tenure_months`): `weight_X1 = -0.5554` ($|w| = 0.5554$), `odds_ratio_X1 = 0.5739`
  3. $X_2$ (`complaint_count_90d`): `weight_X2 = 0.5505` ($|w| = 0.5505$), `odds_ratio_X2 = 1.7341`
  *Domain interpretation of the largest odds ratio ($X_3$):* Holding all other variables constant, each one standard deviation increase in a customer's discount order share (~22.8 percentage points) multiplies the odds of churn by **2.4629** (a ~146% increase in churn odds), identifying deal-sensitive discount seekers as the highest-risk segment for defection once promotional incentives subside. Conversely, higher customer tenure protects against churn (`odds_ratio_X1 = 0.5739`, reducing odds by ~42.6%), while complaints significantly accelerate churn (`odds_ratio_X2 = 1.7341`, increasing odds by ~73.4%).

- **R2.3 (Accuracy Trap & Threshold Adjustment):** A naive baseline that blindly predicts zero churn for all customers achieves `blind_accuracy = 0.7875` (78.75%), which sits remarkably close to the default logistic regression accuracy `tau_0.5_accuracy = 0.8042` (80.42%). Accuracy alone is deeply misleading because active customers dominate the base (~78.75%); a model that simply ignores all churners scores nearly 79% accuracy while delivering zero business utility, and the $\tau = 0.5$ model misses more than half of all churners (`recall = 0.4706`, leaving 27 of 51 churners undetected). Lowering the decision threshold to the classification benchmark $\tau = 0.30$ substantially elevates recall from **47.06% to 74.51%** (catching 38 of 51 churners), while precision adjusts moderately from **54.55% to 46.34%** ($F_1 = 0.5714$, false alarms increasing from 20 to 44). Note that this benchmark threshold $\tau = 0.30$ is distinct from the financially optimal deployment threshold $\tau = 0.1500$ derived in Task 2.8.

- **R2.4 (Logistic Regression vs. KNN Benchmark):** Comparing the logistic regression model at the classification benchmark $\tau = 0.30$ against the cross-validated $K$-Nearest Neighbours classifier ($K = 5$):
  - **Logistic Regression ($\tau = 0.30$):** `f1 = 0.5714`, `recall = 0.7451`
  - **KNN ($K = 5$):** `knn_f1 = 0.3696`, `knn_recall = 0.3333`
  The logistic model vastly surpasses KNN, delivering more than double the recall (74.51% vs 33.33%) and a markedly superior F1 score (0.5714 vs 0.3696). Because standard Euclidean distance weights all seven dimensions equally without recognizing directional feature relationships, majority voting in KNN breaks down under class imbalance and misses two-thirds of at-risk customers.

- **R2.5 (Financial Cost Optimization & Deployment Decision):** For commercial deployment, we recommend operating the **logistic regression model at the financially optimal alert threshold $\tau = 0.1500$** (selected strictly on the 560 training rows where total cost is minimized at INR 12,150, `cost_train_at_tau = 12150`). On the unseen hold-out test set (240 records, 51 positive churners), operating at $\tau = 0.1500$ yields:
  - Confusion counts: $TP = 45$, $FP = 73$, $TN = 116$, $FN = 6$
  - Test metrics: `recall = 0.8824` (88.24% of churners captured), `precision = 0.3814`, `f1 = 0.5325`
  - Financial test cost: `cost_test_at_tau = 6050` INR ($50 \times 73 + 400 \times 6 = 3650 + 2400$)
  This cuts operational losses by **48.7%** compared to the standard threshold cost `cost_test_at_0.5 = 11800` INR ($TP=24, FP=20, TN=169, FN=27 \implies 50 \times 20 + 400 \times 27$) and slashes losses by **70.3%** compared to flagging nobody `cost_test_flag_nobody = 20400` INR ($400 \times 51$). Selecting the threshold strictly on training data prevented optimistic data leakage and guaranteed an honest, out-of-sample financial evaluation.

- **R3.1 (WCSS Drops & Elbow Selection):** The four successive within-cluster sum of squares (WCSS) drops across $K \in \{2, 3, 4, 5, 6\}$ are:
  - $\text{WCSS}(2) - \text{WCSS}(3) = 2262.6753 - 1602.8471 = \mathbf{659.8282}$
  - $\text{WCSS}(3) - \text{WCSS}(4) = 1602.8471 - 1494.7732 = \mathbf{108.0739}$
  - $\text{WCSS}(4) - \text{WCSS}(5) = 1494.7732 - 1323.7157 = \mathbf{171.0575}$
  - $\text{WCSS}(5) - \text{WCSS}(6) = 1323.7157 - 1278.1691 = \mathbf{45.5466}$
  The task's mathematical elbow criterion selects **`elbow_k = 3`** as the smallest $K \in \{3, 4, 5\}$ satisfying $\text{WCSS}(K) - \text{WCSS}(K + 1) < 0.5 \times (\text{WCSS}(K - 1) - \text{WCSS}(K))$, since $108.0739 < 0.5 \times 659.8282 = 329.9141$. While the successive drops do not shrink monotonically (the drop temporarily rebounds from $108.0739$ at $K=3 \to 4$ to $171.0575$ at $K=4 \to 5$ because the pinned starting rows produce a strictly reproducible benchmark rather than a guaranteed global optimum for every $K$), $K = 3$ represents the primary structural elbow where the rate of variance explanation experiences its steepest transition.

- **R3.3 (Hierarchical Linkage Comparison & Dendrogram Cuts):**
  - **Single Linkage (`single_clusters_at_cut = 4`):** The largest merge height gap occurs between merge 2 ($1.4000$) and merge 3 ($2.8000$) with a gap of $1.4000$. Cutting here produces **4 clusters**: `{E1}`, `{E4}`, `{E5}`, and `{E2+E3+E6}`.
  - **Complete Linkage (`complete_clusters_at_cut = 2`):** The largest merge height gap occurs between merge 4 ($2.9000$) and merge 5 ($7.9000$) with a massive gap of $5.0000$. Cutting here produces **2 clusters**: `{E1+E4+E5}` and `{E2+E3+E6}`.
  - *Why they disagree:* Single linkage computes proximity as the minimum distance between any single pair of members; due to "chaining", the presence of a single moderate intermediate connection between E5 and E6 (distance $3.4$) allows all cohorts to merge at very low height (final height $3.4000$), obscuring the deeper macro split and falsely magnifying the early gap between heights $1.4$ and $2.8$. In contrast, complete linkage evaluates cluster compactness by requiring the maximum pairwise distance between all members to remain small; the large dissimilarity between opposing cohorts (e.g., distance between E1 and E2 is $7.9$) creates an enormous final jump from $2.9$ to $7.9$, correctly identifying two coherent, isolated macro clusters `{E1, E4, E5}` and `{E2, E3, E6}`.

## Part 4 findings

- **R4.1 (Decision Tree Splits & Stopping Rules):** Among the four candidate questions on the 560 training records, candidate split **S4 ($X_1 \le 24$ months customer tenure)** is the best split, achieving the highest information gain (`info_gain = 0.1252`) and highest Gini gain (`gini_gain = 0.0606`). It separates customers into an acute high-churn newer group (churn rate $45.74\%$, 86 of 188) versus a resilient tenured group (churn rate $8.87\%$, 33 of 372). A decision tree grown until every terminal leaf is completely pure overfits severely because it memorizes idiosyncratic training noise, sample-specific anomalies, and stochastic variance rather than underlying population patterns, resulting in poor generalizability on unseen data. One standard stopping rule that prevents recursive overgrowth is enforcing a maximum tree depth (`max_depth`) or setting a minimum sample count threshold per leaf (`min_samples_leaf`).

- **R4.2 (Model Deployment Recommendation & Ensembling Analysis):** Among the five structured models evaluated on the 240 out-of-sample test records in `part4_voting.csv` at the classification benchmark threshold $\tau = 0.30$, we recommend shipping the **standalone Logistic Regression model**, which delivers the superior balance with `f1 = 0.5714` and `recall = 0.7451` (successfully flagging 38 of 51 test churners). Combining models failed to improve performance: hard voting reduced both metrics to `f1 = 0.5344` and `recall = 0.6863`, while soft voting yielded `f1 = 0.5507` and `recall = 0.7451`. Multi-model combinations degraded predictive power because the ensemble was dragged down by the poorly calibrated K-Nearest Neighbours classifier (`knn_f1 = 0.3696`, `knn_recall = 0.3333`), demonstrating that ensembling only outperforms single models when all component base learners provide high-quality, mutually complementary decision boundaries. For financial deployment, calibrating this standalone logistic model to $\tau = 0.1500$ captures 88.24% of churners at minimum operational cost.

- **R4.3 (AdaBoost Reweighting & Hypothesis Trust):** Following round 1 normalization, the two misclassified points (points 3 and 7) each received an updated sample weight of $0.2500$, giving them a combined total weight of **`0.5000`** (exactly half the entire weight mass of the eight-point training set). Round 2 places substantially higher trust in hypothesis $h_2$ ($\alpha_2 = 0.8047$) compared to hypothesis $h_1$ ($\alpha_1 = 0.5493$) because $h_2$ achieves a lower weighted error on this reweighted sample ($\varepsilon_2 = 0.1667$ versus $\varepsilon_1 = 0.2500$), correctly resolving the difficult instances penalized by the previous round.

  - **Model B (RNN — Customer-Review Topic Classification into 16 Topics) Weight Dimensions & Sequence Invariance:**
    For sorting customer-review text token sequences into 16 topics, the transition and projection weight matrices have dimensions:
    - $W_{xh}$: shape $128 \times 64$ (8,192 parameters)
    - $W_{hh}$: shape $128 \times 128$ (16,384 parameters)
    - $W_{hy}$: shape $16 \times 128$ (2,048 parameters)
    - Total parameters `rnn_total = 26768` (including 128 bias terms $b_h$ and 16 bias terms $b_y$).
    The total parameter count `rnn_total` does not grow when input review text sequences become longer because recurrent architectures share the exact same weight matrices ($W_{xh}, W_{hh}, W_{hy}$) across every recurrence step regardless of sequence length.
  - **Recommended Activations and Loss for 10 Classes:**
    For hidden layers, use **ReLU** (Rectified Linear Unit) for fast, non-saturating gradient propagation; for the 10-class output layer, use **Softmax** paired with **Categorical Cross-Entropy Loss** to produce normalized posterior class probabilities.
  - **Vanishing Gradients and Skip Connections:**
    In very deep plain neural networks, repeated backpropagation multiplications by fractional weight matrices and activation derivatives cause gradient signals to diminish exponentially as they travel backward, causing early layers to stall and stop learning. A residual skip connection ($x + F(x)$) resolves this by establishing an uninterrupted identity shortcut that allows gradient signals to flow directly from later layers back to initial layers without attenuation.

Neither Model A (catalog image sorting) nor Model B (customer-review topic classification into 16 topics) is worth building before this structured tabular model is deployed in production. Tabular transaction signals provide immediate, high-margin retention lift with minimal compute, whereas deep learning architectures add substantial infrastructure complexity without addressing core customer defection drivers.

## Limitations

1. **Synthetic Data Constraint:** The dataset was generated from a synthetic parametric process (`generate_data.py`), which lacks the complex real-world anomalies, catalog shifts, missing fields, regional payment failures, and macroeconomic shocks encountered in live Flipkart production environments.
2. **Single 70/30 Split and Sample Imbalance:** Model validation relies upon a single fixed partition yielding only 51 positive churn events in the hold-out test set; performance estimates carry finite-sample uncertainty, and robust deployment requires longitudinal backtesting across multiple successive sales quarters.
3. **Static Cost Assumptions:** The financial optimization assumes uniform, static operational costs (INR 50 per false positive coupon, INR 400 per false negative lost margin) across the entire customer base, whereas true customer lifetime value (LTV) and promotional elasticity vary substantially between low-spend bargain hunters and high-value loyalists.
